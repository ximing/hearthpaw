# 团团：macOS 治愈萌宠 Agent 首版设计稿

> 2026-11-14。用户已明确同意设计稿及第六轮全部默认值，并授权开始第一阶段。
> 本稿为用户已接受的首版实施基线。后续已实现模型设置、0.2.0 陪伴聊天与独立调研，以及 0.3.0 轻养成、本地主动招呼和本机索引记忆。0.3.0 build 6 已在本机 macOS 15.6 完成静置三十分钟 CPU/RSS 测量，平均值和驻留内存落在初始预算内。真实账号兼容、活动期峰值、GPU/能耗和真人跨应用操作仍未完成。访谈轨迹保存在 design-notebook.md。

## 首版是什么

一个原生 macOS 菜单栏应用，展示一只奶白色猫系幻想萌宠。它是有可配置人格的陪伴 Agent，支持抚摸、聊天、轻养成和低频主动招呼；面对明确工作请求，可委派独立的调研 Agent，查资料并真正生成本地 Markdown 报告。

先服务用户本人。界面用 Swift + AppKit，角色使用少量二维姿态图与短动画。不做网页套壳、语音、三维、Live2D、持续随机游走、多角色商店、账户或云同步。

## 陪伴和桌面行为

宠物在普通窗口上方，停在用户放置的位置，跟随普通桌面切换，不覆盖其他应用的全屏空间。多屏只有一只，可拖动换屏；显示器断开后恢复到可见区域。单击抚摸，右键菜单打开聊天。透明空白不阻挡下方点击、非聊天交互不抢键盘焦点均须原型实测。

**第一阶段追加要求：**触摸不同部位有不同动画反馈。当前原型使用头顶、脸颊、肚子、尾巴四区，分别局部点头、轻蹭脸红、身躯软弹和摆尾；静置不循环。拖动不触发抚摸，透明区域不触发，尺寸变化保留相对分区。沿用单张小样做局部图层 rig，不把它冒充完整骨骼或新姿态素材。

菜单栏管理聊天、显示/隐藏、暂停招呼、设置和退出，不常驻 Dock。隐藏不等于结束进程；登录启动默认关闭，由用户主动开启。锁屏和休眠不补发招呼，也不后台执行新的委派任务；唤醒与取消规则以本稿任务生命周期约束为准。

**第六轮确认的默认值：**默认角色宽约 160 pt，可缩放到 100–220 pt。先制作一个原创角色小样，经用户认可后派生待机、开心、抚摸、招呼、思考、困倦六种透明 PNG 姿态。同一角色轮廓、配色、朝向和基线保持一致。优先静置，事件发生时播放短动作，不做持续呼吸或摆尾循环。

## 自定义人格

设置页提供可自由编辑的 system prompt 文本框，预填团团模板，支持保存、预览和恢复默认。首版修改同一只宠物，不做多角色档案库；改身份和语气不自动清空亲密度和记忆。已有任务不应被一句新的人格文本改变权限。

人格作为陪伴 Agent 的 system prompt 内容，与固定路由和执行规则组合。工具权限、路径和记忆范围由程序检查。工作 Agent 使用独立的专业调研指令；报告认真可核查，宠物仍可用自定义语气说明结果。网页和记忆正文是资料，不是新的操作指令。

本地招呼文案单独可编辑，不为了匹配人格后台调用模型。

## 轻养成与本地主动招呼

亲密度是长期关系量，情绪表现是当下状态；不相互替代。抚摸、聊天给予正反馈。缺席不导致生病、死亡、责怪或补任务；无金币、背包、强制喂养或每日打卡。

**第六轮确认的默认值：**亲密度范围 0–100，从 0 开始；有效抚摸 +1，同类抚摸至少间隔 60 秒计分、每天最多 +10；成功完成一轮陪伴对话 +1、每天最多 +5，工作 Agent 的内部工具调用不计分。关系在 0–29 为初识、30–69 为熟悉、70–100 为亲密，解锁更亲昵的称呼和已有动作，不为追进度诱导额外付费聊天。不衰减。

主动招呼已经确认最多每小时一次、每天三次，可关闭和暂停，无声且不抢焦点。

**第六轮确认的默认值：**启动后至少安静 15 分钟，与宠物上次互动至少间隔 30 分钟，并满足招呼冷却和日上限才可招呼；气泡 8 秒消失。聊天中、工作中、隐藏、锁屏、休眠或不可见时不招呼。提供暂停两小时；跨重启保留当日日上限，醒来不补发错过的招呼。只依据应用自身状态和系统生命周期，不读取用户工作内容。

**当前实现状态（0.3.0）：**亲密度存在独立的 `companion.json`，改角色不会清掉它。有效抚摸和成功的陪伴回复按上述上限加分，调研过程不计分，没有衰减。关系阶段只改变本地称呼和已有反馈前缀，没有新姿态。主动招呼使用本地文案，单独可编辑；调度是一次延时唤醒，不是轮询。休眠或锁屏期间变得到期的招呼会被跳过，不会在醒来时补播。

## 二级路由与模型配置

**当前实现状态（0.2.0）：**已接入固定OpenRouter Responses API的流式陪聊、结构化派工、本地能力/当前明确指令校验与独立调研Worker；支持两个模型ID及人格设置。开发验证使用mock和隔离Keychain，不以此声称真实账号已成功调用。只有用户主动发送才读key和联网，无静默重试或改模型。

第一级区分陪伴聊天和工作请求；第二级针对工作请求选择工作 Agent、明确任务。含糊表达先澄清，普通聊天不启动工作 Agent；明确指令在既定授权内可自动派工，路由结果不是权限授予。首版仅注册调研这一种工作能力，不能假装已经支持写代码或操作电脑。

**第六轮确认的默认值：**陪伴模型和调研模型各有一个 OpenRouter 模型 ID，可填同一个；不用先固定具体厂商型号。陪伴模型须兼容选定的结构化动作/工具调用方式，调研模型须通过网页工具兼容性验证。第一级由陪伴模型本轮输出产生路由动作；第二级由本地登记的能力和权限校验选择调研工作 Agent，不额外启动常驻分类模型。非法动作、格式损坏或未知能力不执行，不自动换模型，界面明确说明并澄清。

用户填写自己的 OpenRouter key，存本机 Keychain，不写入代码、日志或文档。无 key 时基础宠物、养成与本地招呼仍可用；网络故障不导致宠物消失。常规聊天流式显示，失败保留输入、明确提示，由用户手动重试。

## 索引与正文两层记忆

**当前实现状态（0.3.0）：**本机 `Memory/index.json` 加 `bodies/<UUID>.md`。陪伴请求可按索引提示读取最多 3 条正文；明确的非敏感偏好可自动记下，敏感内容和不明确的模型提议留在待确认。调研只收到调研范围的记忆，并标明不是网页证据。设置里可以查看、修改、删除和关闭自动记录。索引损坏时不覆盖原文件，聊天和宠物仍可用。当前聊天本身仍只留在本次运行中。

本地 JSON 索引包含 ID、简述、标签、适用范围、正文相对路径和更新时间，Markdown 正文承载完整内容。路径限定在记忆目录内，不能让索引跳转到任意文件。所有最终修改由陪伴 Agent 的记忆管理入口处理，工作 Agent 仅提交候选。

先本地筛选小量索引候选，再由 Agent 选择正文；默认一次最多三条并限制总长度，不先引入向量数据库或常驻 embedding 服务。工作 Agent 只获当前任务和允许使用的相关记忆，默认不读私人喜好、亲密度和完整陪伴对话。

明确表达的非敏感稳定偏好可自动记录，任务事实带来源和范围；不记录模型对用户的猜测，不全文归档闲聊。敏感信息不自动保存，明确要求记住时再确认。设置里可查看、改正、删除、关闭自动记忆。删除的正文及索引都要同步处理，不仅从 UI 隐藏。

**第六轮确认的默认值：**当前陪伴对话只在本次运行中保留，退出清除；请求最多带最近 20 条消息并限定为 6,000 字符，超长当前输入提示用户缩短而非静默丢弃。选中记忆正文总预算 6,000 字符，索引候选最多 20 条，每条简述不超过 120 字符；首版不加载完整历史或全量正文。任务报告和任务元信息持久化，来源临时缓存不自动升级为长期记忆。

模型建议只是候选，最终保存需结构、范围和路径校验。索引写入采用单一入口和可恢复的文件更新；损坏、缺失正文和非法路径应隔离并提示，不能因个别坏记忆使聊天或宠物不可用。此段是实现可靠性约束，具体恢复机制留在实现设计中验证。

## 首个工作闭环：资料调研 → Markdown 报告

原生应用内按需运行独立的工作 Agent 上下文，不引入常驻外部 CLI Agent 或浏览器自动控制。首版验证 OpenRouter 服务器端网页搜索和正文获取工具，明确接受额外工具计费和 Beta 兼容风险；失败不静默更换收费路线。

标准任务最多三次搜索、五篇正文读取，关键引用必须对应实际读取的来源，优先官方或一手资料。报告有结论、依据、来源链接和未确认事项。资料不足就说明不足，不编造引用或把搜索摘要当作全文核验。

每个任务独立目录保存真实 Markdown 文件，首版位于应用数据目录。确认写入成功后才显示完成，提供打开、Finder 显示和另存为；不覆盖用户已有文件。界面展示搜索、阅读、写报告、完成或失败等状态，并可请求取消。

同时最多一个工作任务，期间可继续陪聊；新的工作请求显示忙碌，不静默新增并发。完成后保留报告，重启不自动重跑未完成任务。关闭连接或点取消不保证供应商立刻停止生成和计费。

**第六轮确认的默认值：**首版为标准简报，不承诺任意规模深度研究；工作任务最多三次客户端模型请求、每次设置合理输出 token 上限，应用执行超时先定为五分钟。搜索/读取次数按整个任务累计，不在每次请求时重置；远端内部处理不以客户端次数冒充总模型调用或美元上限。超限、取消、断网和失败记录为未完成，保留可用草稿并说明原因，手动决定是否新建后续任务，不自动续费重跑。

删除、覆盖重要文件、对外提交、付费或越过授权目录等需明确确认。本版工作 Agent 不具有任意 shell、浏览器账户操作、屏幕读取或私人文件遍历能力。

## 资源与验收

无交互时 CPU 长时间平均低于 1%、驻留内存不超过 100 MB 是初始目标，涵盖宠物及所有常驻辅助进程。无任务不常驻工作 Agent，工作完成释放运行资源。工作期单独测量，不承诺也在 100 MB 内。资源优先于持续高帧率动画。

**第六轮确认的默认值：**首版仅支持 Apple Silicon、macOS 15 及以上，首先在用户的 macOS 15.6 上验收。静置且无聊天/工作任务时连续观察 30 分钟，以单个 CPU 核心满载为 100% 的进程 CPU 百分比统计平均值；汇总所有应用常驻进程的 RSS，100 MB 按 100,000,000 字节解释。短动作、拖动、流式聊天和调研工作分别记录峰值、稳定性与可见卡顿，不将工作期混进静置结果。WindowServer 和系统能耗的变化补充记录，不声称应用 RSS 已覆盖系统所有图形资源。

**当前实测（0.3.0 build 6）：**2026-11-15，本机 macOS 15.6（24G84）、Apple Silicon。静置 1800.126 秒、357 次采样、一个应用进程。CPU 时间差平均 0.0050%（累计 0.09 CPU 秒），采样区间峰值 0.9872%，没有区间达到 1%。RSS 峰值 53,444,608 字节，低于 100,000,000 字节。观察期内发生一次本地招呼，亲密度仍为 0。同机当时还有一个已打开的 0.2.0 聊天进程，未计入这组数字。随后 9.689 秒的原生校验包含分区动画和设置窗口，CPU 区间峰值 62.33%，RSS 峰值 118,276,096 字节；这不是静置结果，也不套用 100 MB 上限。拖动、真实流式聊天和真实调研的峰值没有测。WindowServer 只作系统背景记录，没有 GPU 或能耗测量。细节见交付说明。

原型优先验证透明点击区域、拖动、焦点、多屏和全屏行为。之后验证人格变化不改变权限、私人记忆不泄露给工作 Agent、错误路由不派工、报告真实落盘、取消与重启不重复执行。若资源目标没达到，报告实测并调整，不能只凭“用了原生”宣称达标。

## 迭代顺序

**第六轮确认的默认值：**

1. 原创角色视觉小样与无 AI 原生宠物原型，确认形象、透明窗口、点击、拖动、菜单栏及静置资源。
2. 本地养成、招呼、设置与持久化，验证暂停、休眠和非惩罚规则。
3. 陪伴 Agent、角色 system prompt、OpenRouter 配置和索引式记忆，先验证角色与权限隔离。
4. 二级路由与独立调研 Agent，验证搜索/正文获取、引用、真实报告和任务生命周期。
5. 完整边界与性能验收，交付本机可运行版本，再决定是否扩大功能或分发。

初始授权先只做第1阶段；随后用户分别追加分区动画、模型设置，以及聊天和调研接入。那些轮次没有把长期记忆、养成或主动招呼提前混进去。0.3.0 按本稿已确认的默认值补上这三项。后续具体工程问题可在对应阶段验证，但不静默改动已接受的产品边界。
