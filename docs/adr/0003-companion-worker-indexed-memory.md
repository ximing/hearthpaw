# 陪伴 Agent 委派工作，记忆采用索引与正文两层

用户希望萌宠不仅陪聊，还能完成真实工作，因此不采用单一聊天入口承载全部能力。陪伴 Agent 负责交流与理解意图；第一级区分陪伴聊天和工作请求，第二级选择工作 Agent 并形成明确任务。这是职责划分，不要求每条消息额外固定调用两个模型。首个工作闭环为资料调研并生成本地 Markdown 报告。

长期记忆分为本地索引文件和记忆正文文件。索引描述条目、适用线索和正文路径，正文按需读取，而非每轮将全部记忆注入上下文。“两层”不指短期和长期两个库，当前对话上下文另行设计。

工作 Agent 只收到本次任务与允许使用的相关记忆，不默认继承完整陪伴聊天、个人喜好或亲密度。陪伴 Agent 统一管理记忆索引，工作 Agent 可以提交候选记忆，但不直接任意修改共用索引。自动写入、用户批准、具体文件格式及一致性处理仍待确认。

明确工作指令在既定授权内可以自动派工，含糊表达先澄清；路由结果不是权限授予。删除、覆盖重要文件、对外提交、付费及越过工作目录等动作需要明确确认。首版调研的搜索工具、源网页读取方式和报告落盘位置尚未选择，因此本决定不授权任意 shell、浏览器控制或文件遍历。

低资源预算包含宠物及所有常驻辅助进程。无任务时不常驻工作 Agent；任务按需运行，默认最多一个工作 Agent，完成后释放运行资源。工作期的资源与费用单独测量，不承诺仍在 100 MB 内，也不通过隐藏子进程排除开销。新增调用、任务生命周期和记忆管理复杂性是相较仅陪聊方案的代价。

本决定替代 ADR 0002 中“全系统只能文字辅助、不能生成真实文件”的旧限制。无声、不自动观察屏幕或监听剪贴板及麦克风、本地招呼不请求模型、无 key 时基础宠物仍可用等约束继续保留。常规聊天失败明确提示并手动重试，任务级恢复策略另行确认。
