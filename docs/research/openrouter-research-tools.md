# 调研工作 Agent 的最小工具路线

首版可以优先验证 OpenRouter 的服务器端网页搜索与正文获取工具，再由 Mac 应用把最终报告保存成 Markdown 文件。这样无需先引入本机浏览器自动化或常驻外部 Agent 守护进程；这是针对首版调研任务的建议，尚未获得用户确认，也没有调用付费接口。

查证日期：2026-11-14。作者：Manus AI。

## 搜索和正文获取是不同步骤

官方 `openrouter:web_search` 支持多种搜索引擎、单次结果数、使用次数和总结果数等参数。Exa 返回与问题相关的页面摘录，而不是保证返回全文。原生供应商搜索可能忽略部分限制，因此如果依赖明确的次数和内容预算，应验证并固定支持相应参数的引擎，而不是假定所有模型的原生搜索都相同。[1]

`openrouter:web_fetch` 可以获取指定 URL 的文本、标题和地址。可限制调用次数、域名和返回内容长度，并返回失败状态；正文过长会截断。[2] 搜索后应读取关键来源，引用必须对应实际获取的来源，不能仅凭标题或搜索摘要声称核验了原文。

服务器工具处于 Beta，接口与行为可能改变。账号的隐私、区域与工作区工具设置也可能限制调用；必须用选定模型和实际账号做兼容性验证，失败要明确显示，不能悄悄改成另一种计费工具。[1] [2]

## 费用不能仅用模型 token 估计

截至本次查证，Exa 搜索 `auto` 模式文档列示每次请求 0.007 美元，其他模式可更高。[1] 网页获取的 `openrouter` 引擎列为免费，但处理正文的模型 token 仍然收费；其他正文引擎可能另收费。[2] 这些是页面公布的工具价格，不是整个调研任务报价，实施前需再次核对。

可以从固定搜索和正文读取次数、小量来源、限定内容长度的标准调研开始，再设置任务级模型调用和时间预算。次数限制不是最终美元硬上限，模型、输入长度和供应商会影响实际费用。

## 报告写入仍由本机控制

OpenRouter 的普通客户端工具调用只是模型提出函数及参数，由客户端执行并回传结果；模型发出一个工具名不等于文件已经写入。[3] 服务器端网页工具也不会自动在用户的 Mac 上创建报告。应用必须在允许的任务目录内真正写入报告，验证文件存在后才能向宠物返回成功和可打开的文件位置。

建议陪伴 Agent 与工作 Agent 使用独立的模型上下文。调研工具权限和报告目录由程序控制，不因用户编辑宠物人格 prompt 或网页中的文字而扩大。网页和记忆正文作为资料，不作为新的权限或操作指令。
