# 0.3.0 养成、招呼与索引记忆

按已接受的 MVP 默认值实现，没有新增姿态、向量检索或后台模型。

## 养成

`~/Library/Application Support/TuanTuan/companion.json` 与 `settings.json` 分开。亲密度 0–100，从 0 开始。有效抚摸 +1，同一部位至少隔 60 秒，每天最多 +10。成功的陪伴回复 +1，每天最多 +5。调研、工具调用、取消和失败回复不计分。不衰减。0–29 初识，30–69 熟悉，70–100 亲密，只改本地称呼和已有反馈前缀。文件损坏时停止计分，不覆盖原文件；设置里确认后才能换成空白记录。

## 主动招呼

本地文案，不请求模型，无声，气泡不成为键窗、忽略鼠标。启动后安静 15 分钟，距上次互动至少 30 分钟，每小时最多一次，每天最多三次。可关闭，可暂停两小时。聊天窗口开着、回复中、调研中、隐藏、不可见、锁屏或休眠时不招呼。当日次数、暂停和上次互动会留下；15 分钟安静期不跨进程保留。醒来不补播睡着期间到期的招呼。调度是下一次时间的单次 `asyncAfter`，没有秒级轮询。自定义文案在各关系阶段替换默认句；留空则按亲密度使用默认句。

## 记忆

`~/Library/Application Support/TuanTuan/Memory/index.json`、`pending.json` 和 `bodies/<UUID>.md`。相对路径必须是 `bodies/<UUID>.md`。目录以 `O_NOFOLLOW` 打开，不跟随符号链接或硬链接。本地先筛最多 20 条索引，再读最多 3 条正文，合计不超过 6,000 字。没有 embedding。

只有用户原句里明确的非敏感偏好会自动写入陪伴范围。敏感启发式包括口令、密钥、证件、病历、住址、邮箱和大陆手机号。其余模型提议留在待确认，且正文必须等于当前用户原句。调研上下文只含调研范围，前缀是 `M1`，并写明不是网页证据。陪伴请求在没有记忆库时仍只有 `delegate_research`。有记忆库时才增加 `propose_memory`，索引非空才增加 `read_memory`。读正文最多再发一次陪伴请求，正文放在指令里，不写入聊天历史。

设置「养成」页可改开关、文案、条目和待确认队列。删除同时移除索引和正文。索引损坏时不覆盖，聊天和宠物继续可用。聊天记录本身仍只在本次进程内存中。完成的报告不会自动入库；聊天窗口的「记为任务事实」只接受已完成并落盘的报告主题。

## 验证边界

离线 XCTest 117 项 0 失败，scratch 在 `.work/ai-030`。未读取生产 key，未发起付费模型请求。这不能说明用户的 OpenRouter 账号或所选模型已经调用成功。

`--validate-agent-at` 在 build 6 上全部通过。`--validate-at` 中分区、动画、原有三页设置，以及注入养成和记忆后出现第四页「养成」，这些检查通过。同一次从终端启动时，设置窗口没有成为 `keyWindow`，九项 Command-V / Command-A 检查因此失败；快捷键实现没有改。校验用的养成和记忆文件放在该次校验目录里，不写用户的正式数据。

静置资源使用 `--observe-idle-at`。这个参数只改养成文件和记忆目录的位置，不打开聊天、设置或校验。2026-11-15，macOS 15.6，Release 0.3.0（build 6）静置 1800.126 秒：357 次采样，一个进程，CPU 时间差平均 0.0050%，区间峰值 0.9872%，RSS 峰值 53,444,608 字节。平均 CPU 和 RSS 都在初始预算内。约 916 秒时出现一次本地招呼，`greetingsToday` 为 1，亲密度仍是 0。用户 Application Support 的文件清单没有变化。随后单独观察 9.689 秒原生校验，CPU 区间峰值 62.33%，RSS 峰值 118,276,096 字节；其中包含分区动画和设置窗口，不并入静置结果，也不套用 100 MB 上限。拖动、真实流式聊天和真实调研没有做资源峰值测量。WindowServer 在静置窗口内累计 388.68 CPU 秒，RSS 从 80,412,672 字节降到 75,792,384 字节，不能归因给团团。没有 GPU 或能耗数据。同机一个已经打开的 0.2.0 聊天进程没有关闭，也没有计入上述合计。
