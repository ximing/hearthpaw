# macOS 治愈萌宠 Agent：设计访谈笔记

> 阶段：脑暴已收束。0.3.0 已实现养成、本地招呼和索引记忆。静置三十分钟 CPU/RSS 已在 0.3.0 build 6 上测量；真实账号、活动期资源、GPU/能耗和真人桌面体验仍待验收。
> 创建日期：2026-11-14；更新节点：第六轮全部确认并授权第一阶段，当前实施基线见 mvp-design.md。
> 未回答的建议不视为接受；新需求与旧边界发生冲突时记录取舍，不静默覆盖。

## 产品目标

一个在 Mac 上长期驻留、低资源占用的二次元治愈萌宠。它本身是陪伴 Agent，支持陪伴、轻养成和真实工作委派，可以调用 OpenRouter。首版先由用户本人使用，不以公开分发、上架、账户、云同步或商业化为目标。

## 已确认的宠物体验

默认角色暂名团团：奶白色、圆润的猫系幻想小生物，小耳朵、短爪和蓬松尾巴，柔和绘本式二次元。中文短句、温柔不黏人，陪聊可爱、帮忙认真，不用情感负担要求陪伴。

单击抚摸、拖动位置、右键打开文字聊天；平时停在用户放的位置，偶尔短动作，不持续随机游走。首版无声，不做语音输入或朗读。亲密度与情绪表现提供正反馈；缺席不生病、死亡、责怪或要求补作业，没有金币、背包、强制喂养或每日任务。

主动招呼采用本地文案，不请求模型，默认最多每小时一次、每天三次，可关闭和暂停。不抢焦点、不播放声音，忽略无需处理。触发条件、气泡时间、暂停与跨日统计待定。

## 已确认的桌面与应用路线

Swift + AppKit 原生窗口和界面，使用少量二维姿态图配短动画，不做 Web 套壳、Live2D 或三维角色。原生界面路线不等于已选工作 Agent 的运行实现。

普通窗口上方、跟随普通桌面切换，不覆盖其他应用的全屏空间；多屏只有一只，可拖到其他屏，断开显示器后恢复可见位置。平时不抢输入焦点，主动聊天时才接收键盘。透明空白区域不阻挡下方点击是需要实测的验收目标。

菜单栏管理，不常驻 Dock；提供聊天、显示/隐藏、暂停招呼、设置和退出。隐藏不等于退出；登录启动默认关闭，由用户主动开启。

## 第四轮确认的 Agent 架构

用户回答“同意，Q3 先做资料调研并生成 Markdown 报告”，接受了第四轮全部六项建议。

### 二级路由与首个真实任务

第一级区分陪伴聊天与工作请求。普通闲聊由陪伴 Agent 回答；第二级针对工作请求选择工作 Agent，并形成明确任务。这是职责划分，不要求每条消息额外调用两个模型。

首个闭环：用户交给宠物调研主题，工作 Agent 查资料并生成本地 Markdown 报告，宠物回传结果。报告必须是真实产物，不只是气泡里的承诺。具体搜索工具、网页获取方式、任务步骤和报告落盘位置待定。

### 两层记忆

第一层为本地索引文件，记录记忆简述、适用线索和正文路径。第二层为对应正文文件，需要时读取，不每轮注入全部记忆。“两层”不是短期/长期两个库，当前对话上下文另行设计。

工作 Agent 只接收本次任务和被允许使用的相关记忆，不默认继承完整聊天、个人喜好或亲密度。陪伴 Agent 是统一记忆管理入口，工作 Agent 可以提交候选记忆，但不直接任意修改共用索引。记忆自动抽取与批准、正文内容组织、容量、检索规则、删除与纠错尚未确认。

### 自动派工与权限

明确工作指令可在既定授权内自动派工；含糊表达先澄清，不把随口想法当成行动授权。删除、覆盖重要文件、对外提交、付费或越过工作目录等需要明确确认。工作状态应对用户可见。

新工作能力取代第二轮“仅文字辅助、所有文件操作都禁止”的旧总限制，但不授权任意 shell、浏览器控制或文件遍历。不自动观察屏幕、监听剪贴板或麦克风继续保留。

### 资源口径

无交互时 CPU 长时间平均低于 1%、应用驻留内存不超过 100 MB 为待实测的初始目标，涵盖宠物及所有常驻辅助进程。资源优先于持续高帧率动画。

无任务时不养着后台工作 Agent；接任务按需运行，默认最多一个工作 Agent，完成后释放运行资源。工作期资源和调用费用单独测量，不承诺仍在 100 MB 内，不通过将开销搬到子进程伪造低开销。

## 新增：用户可配置角色 system prompt

用户明确要求支持设置宠物的身份、角色和回话语气，作为 system prompt。这项能力已纳入需求，而非固定只能使用团团的默认人格。

尚未确认：是结构化字段、自由编辑文本或二者组合；与应用执行规则的组合方式；是否影响工作 Agent；修改角色是否重置记忆与亲密度；本地招呼是否使用该设定。不能将“可编辑 system prompt”默认为允许改变工具权限或覆盖工作任务约束。

## 已确认的 OpenRouter 接入原则

用户在本机填写自己的 key 和模型 ID，key 用本机 Keychain 保存，不进入代码或日志。无 key 时基础宠物可用，AI 对话不可用。常规聊天流式显示，错误明确提示、保留输入并由用户手动重试，不自动换模型或反复请求。取消不保证供应商立刻停止计费。

陪伴与工作模型是否分别配置、具体模型兼容性、任务请求次数和费用上限待定。原第三轮最近 20 条消息、聊天退出清除等建议因记忆重设计未作为已确认规格。

## 当前待决分支

- **角色配置**：编辑方式与提示词组合 → 调研报告风格、身份切换、权限和记忆关系。
- **记忆治理**：自动记录或人工确认 → 私人记忆与任务事实、可查看删除、冲突和过期处理。
- **记忆加载**：索引文件格式、索引增长预算 → 条目选择、正文读取上限、索引一致性与路径安全。
- **调研运行**：工具路线、自建或既有执行器 → 来源核验、引用、报告目录、任务耗时和调用上限。
- **任务生命周期**：可见状态与取消 → 并发聊天、队列、故障、退出后恢复。
- **宠物细节**：养成数值和解锁、动作与素材 → 尺寸、招呼具体策略、静置与动画验收。
- **收束与迭代**：先无 AI 萌宠验证，再养成和招呼，再 AI、两层记忆和调研委派；具体里程碑与最终共同理解需确认。

## 第五轮：最新确认结果

用户回答“都没问题”，接受第五轮完整六项建议。本节是上述第四轮待决项的最新结果；首版完整基线及最后待确认值见 [`MVP 设计稿`](mvp-design.md)。

角色设置采用自由编辑的 system prompt 文本框，提供团团默认模板、保存、预览、恢复默认。单角色可修改，不自动清空亲密度和记忆；本地招呼文案另行编辑。人格影响陪伴表达，工作 Agent 使用独立专业指令，报告默认认真可核查，权限由程序验证。取舍见 [`ADR 0004`](adr/0004-persona-not-permissions.md)。

允许自动记住明确表达的非敏感稳定偏好与有来源的任务事实，不把模型猜测当事实，不全文归档闲聊。敏感信息不自动写入，明确请求记住时再确认；提供查看、修改、删除与关闭自动记忆。最终写入仍走陪伴 Agent 的统一记忆管理入口。

采用 JSON 索引和 Markdown 正文。索引包含 ID、简述、标签、范围、相对路径、更新时间，路径限定在记忆目录内。先本地筛选小量候选，再由 Agent 挑选正文，一次默认最多三条并限制总长度；不先引入向量数据库或常驻 embedding 服务。

工作 Agent 在原生应用内按需运行独立上下文，优先验证 OpenRouter 服务器端搜索及网页正文获取工具，不接外部 CLI Agent 或浏览器自动控制。明确接受工具额外计费和 Beta 风险，需兼容性验证；失败不静默换收费路线。标准任务最多三次搜索、五篇正文读取，引用只对应实际读取来源。

每个任务独立目录保存真实 Markdown 报告，首版使用应用数据目录，提供打开、Finder 显示和另存为。报告含结论、依据、来源与未确认事项。任务状态可见且能请求取消，同时只有一个工作任务，期间仍可聊天；新任务提示忙碌，不静默增加并发。完成后保留报告，重启不自动重跑未完成任务；取消不保证远端立刻停止计费。

最后待收束：角色素材和尺寸、轻养成具体数值、本地招呼的触发与休眠规则、模型配置和路由实现、当前会话保留策略、任务调用与时间预算、性能统计口径和迭代验收。它们会在最后一轮作为一组可修改的默认值提出，尚未视为接受。

## 第一阶段追加：不同部位触摸，不同动作反馈

用户在原型运行过程中明确提出“目前是一个静态图，我需要支持不同地方触摸有不同的动画反馈”。在第一阶段内追加头顶、脸颊、肚子、尾巴四个触摸区域，保留当前角色形象；以现有像素分层与原生图层短动作实现，不引入 Live2D、持续循环动画或新模型请求，不额外生成新姿态。

头顶对应局部点头轻弹，脸颊对应轻蹭与脸红，肚子对应身躯软弹，尾巴对应局部摆动；有分区本地反馈文案。透明像素不触发，拖动仍只移动、结束不误触抚摸，缩放不改变分区。实现属于轻量图片分层 rig，并非完整骨骼、逐帧动画或重绘表情。

静态 0.1.0 的 30 分钟观测已完成：CPU 时间差平均约 0.2872%（单核口径）、RSS 峰值 19,218,432 字节、一个常驻进程。该数据仅属于旧静态基线，不能直接作为新增分区动画版本的验收结果；新版将独立验证并明确其观察时长。

## 分区互动版初测结果

0.1.1 分区互动版五分钟观测完成：300.162 秒、59 次采样，平均单核 CPU 0.2432%，采样峰值 2.5636%，RSS 峰值 30,375,936 字节，一个应用进程。五分钟初测未超初始预算，但不等于新版完整三十分钟性能验收，也没有将 WindowServer/GPU 或系统能耗归因到团团。局部动作质感、透明边缘的真人点击、全屏及物理多屏仍需用户体验确认。

分区互动最终补查：21 项时序动画检查通过，包括正确局部层运动、动作后清理、恢复静态姿态、连续触摸不叠加，以及旧清理不打断新动作。先复现了 AppKit 保留已完成 animationKeys 的情况，确认呈现层已静止后加一次可取消的事件清理；临时状态探针已移除，没有引入持续轮询。

清理修复后的最终构建独立复测完成：300.114 秒、56 次采样，平均单核 CPU 0.1966%，采样峰值 4.1020%，RSS 峰值 34,537,472 字节，一个应用进程。最终交付使用该组数字而非候选版初测；不声称新版三十分钟、GPU/能耗或真人端到端已验收。应用与源码已在 outputs/phase1 准备，操作和完整范围见 Phase1-Delivery.md。
